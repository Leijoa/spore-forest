# 開發流程：比照 BIBI DICE

2026-10-11 阿雷要求比照 BIBI DICE；2026-10-12 改由韻西獨立完成。本文件保留工作包、記憶分層與驗收紀律，依孢子森林的純 HTML／Pages 架構調整，不搬入 Steam、手機商店或 Electron 發行步驟。

## 1. 收斂工作包

韻西讀 SYNC、AGENTS 與任務相關規格，對照實際程式；簡述範圍、預期玩家行為、完成條件與驗證。工作包按 TASK_TEMPLATE 填寫，每批約五項變更以內，限定檔案與不涵蓋的功能。重大數值、存檔、發布等先核對已有授權，僅缺少必要決定時向阿雷確認。

## 2. 韻西實作

韻西依工作包完成程式、測試與模擬，只修改指定範圍並保留其他人的工作。發現產品決策缺口時，先完成不受影響的部分，再集中回報阻斷問題；不套用其他專案玩法。

阿扣已退出本專案，不再派工、重試登入或要求外部審查。原協作腳本與本機忽略目錄中的紀錄僅供歷史追溯。韻西全程負責是正式分工，不需套用接手例外。

## 3. 驗證與差異審查

| 級別 | 適用 | 必做 |
|---|---|---|
| 內容核對 | 純文件／文案 | 真實內容、連結、差異與 git diff --check |
| 聚焦檢查 | 小修正 | 相關測試及直接呼叫端；需要時目視 |
| 整批閘門 | 一般功能／交付 | `node scripts/verify.cjs`，六套瀏覽器檢查及差異空白檢查；最近完整結果 7/7、257 項通過 |
| UI／存檔專項 | UI 或資料變動 | 320／390px、桌面；鍵盤與減少動態；舊檔／非法輸入／重開／匯出匯入／轉生保留 |

韻西記錄差異摘要、PASS／FAIL、反證與未解問題，審查變更及直接呼叫端、權威計算與所有相關 UI，並完成修正。只有修正、失敗或未解疑點才重跑；收尾跑一次整批閘門。數值模擬需配玩家體驗判斷。

## 4. 製作人試玩與發布

先交具體候選版與已完成驗收，讓阿雷確認感受。取得該批所需發布授權後，韻西提交繁體中文摘要、推 main、確認 Pages 工作成功及正式內容已更新。已有同批授權可繼續，不重複詢問。審查或試玩失敗就留在候選版，不宣稱上線。

## 5. 結案與下一步

更新一次 CHANGELOG，SYNC 記實際狀態、結果、阻斷與精確續接點；必要時更新遊戲規格。完成回覆末尾必須依 EXPANSION_PLAN 指出下一個優先工作包，並區分建議、已核准與已實作。

森林經營、批量／長按與前期突破，以及2026-10-13的新聚落、三種菌群和400突破均已發布。下一工作包提案為星海收藏與故事；穿插觀察新階段等待與轉生，再規劃舊菌群後期用途。細節依 EXPANSION_PLAN 最新路線，規劃不等於已實作或已核准所有資料／數值改動。
